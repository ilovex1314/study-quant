# Day01 量化到底是什么

## Today Goal

理解量化投资的本质：量化不是用代码预测股价，而是把投资假设变成明确规则，再用数据验证、用风险约束、用纪律执行。

今天结束后，你应该能把一个模糊投资想法改写成可验证的策略雏形。

## Why This Matters

很多人学习量化时会直接跳到 Python、因子、回测、机器学习。但如果不知道量化在验证什么，代码只会变成复杂版的猜涨跌。

量化真正要回答的是：

```text
这个规则在过去是否有统计优势？
它在什么情况下会失效？
如果错了，我最多可能亏多少？
它是否值得继续观察或执行？
```

## Core Concepts

### 投资假设

投资假设是你对市场规律的一个可讨论判断。

例子：强势资产可能继续强；短期大跌后可能出现反弹；低估值资产长期可能修复。

它解决的问题是把直觉变成可以讨论的研究对象。边界是：假设不是结论，也不是买卖建议。常见错误是把感觉当成事实。

### 规则化

规则化是把模糊语言变成明确条件。

“跌多了买”不是规则；“最近 20 个交易日跌幅超过 8%，并且收盘价重新站上 5 日均线后买入”才是规则。

它解决的问题是让策略可验证、可复现。边界是：规则必须在回测前确定。常见错误是看到结果不好就临时改规则。

### 数据验证

数据验证是用历史数据检查规则过去表现。

它解决的问题是让策略不只停留在观点层。边界是：历史有效不代表未来一定有效。常见错误是只看收益，不看波动、回撤和失败阶段。

### 风险约束

风险约束是限制错误带来的损失。

它解决的问题是让策略在不确定世界中可承受。边界是：风险约束不能消灭风险，只能控制风险暴露。常见错误是策略逻辑讲得通，但仓位太重。

## Underlying Architecture

建议画一张“量化研究漏斗”：

```text
模糊想法
  -> 投资假设
  -> 明确规则
  -> 所需数据
  -> 回测验证
  -> 风险评估
  -> 策略报告
  -> 模拟跟踪
```

每一层都有清晰职责：假设层负责表达观点，规则层负责可执行条件，数据层负责证据，回测层负责模拟，风控层负责约束损失，报告层负责复盘与决策。

## Data And Logic Flow

输入：一个自然语言投资想法。

处理：先抽取其中的市场判断，再改写成条件、周期、数据需求和退出规则。

状态：当前策略处于“研究假设”阶段，不允许直接跳到实盘。

输出：一张策略雏形卡片。

反馈：如果规则无法明确、数据无法获得、风险无法描述，就回到假设层重写。

## Key Technical Points

- 不要从预测开始，要从可验证假设开始。
- 规则要在看结果前确定，避免事后调参。
- 数据字段要提前列清楚，比如日期、收盘价、复权价格、成交额。
- 风险描述必须出现，比如最大回撤、连续亏损、趋势误判。
- 今天不需要写代码，但要为后续代码模块留下接口。

## Production Example

模糊想法：市场跌多了以后可能反弹。

策略雏形：当宽基指数最近 20 个交易日跌幅超过 8%，并且收盘价重新站上 5 日均线时买入；持有 20 个交易日或跌破买入价 5% 时退出。

这个例子不是投资建议，而是展示如何把想法变成规则。

## Counterexample

错误说法：我感觉最近市场差不多到底了，所以应该买。

问题：没有数据范围、没有买入条件、没有卖出条件、没有风险边界，无法验证，也无法复盘。

## Quiz

1. 为什么量化不是简单预测股价？
2. 投资假设和投资结论有什么区别？
3. 为什么“跌多了买”不是合格规则？
4. 一个策略雏形至少要列出哪些数据需求？
5. 为什么历史回测不能直接等于未来收益？

## Review And Reinforcement

- 如果你说不清买入条件，复习“规则化”。
- 如果你只关注收益，复习“风险约束”。
- 如果你把观点当结论，复习“投资假设”。
- 复盘时用一句话总结：这个想法到底要被什么数据验证？
