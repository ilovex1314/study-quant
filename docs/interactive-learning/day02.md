# Day02 一个量化项目从想法到策略报告

## Today Goal

理解一个量化项目的完整流程：从投资想法开始，经过规则、数据、回测、风险评估，最后形成策略报告。

今天结束后，你应该能画出一条策略研究流水线，并知道每一步的输入和输出。

## Why This Matters

Day01 解决“量化是什么”。Day02 解决“量化怎么做”。

很多新手会把量化理解成“写一个程序自动交易”。这太靠后了。真正的顺序应该是：

```text
先研究，再验证，再模拟，再考虑执行。
```

## Core Concepts

### 策略研究流水线

策略研究流水线是一套把想法变成报告的步骤。

它解决的问题是避免凭感觉跳步骤。边界是：研究流水线不保证策略赚钱，只保证研究过程可复盘。常见错误是直接从想法跳到买卖。

### 量化流程画布

量化流程画布是把研究问题、假设、规则、数据、验证和结论放在同一张结构化卡片里。

它解决的问题是帮助初学者看清一个量化项目要经过哪些步骤。边界是：它是学习和研究整理工具，不是额外的投资计划，也不是实盘指令。常见错误是把流程画布误解成必须执行的投资计划。

### 策略报告

策略报告是策略研究的最终产物。

它应该包含假设、规则、数据、回测结果、风险、失败条件和下一步。它解决的问题是让自己未来能看懂当时为什么做这个判断。常见错误是只保留收益截图。

### 反馈循环

反馈循环是根据验证结果回到上游修改假设或规则。

它解决的问题是策略迭代。边界是：反馈不能变成过拟合。常见错误是为了让历史收益更好而不断改参数。

## Underlying Architecture

建议画一张“策略研究流水线”：

```text
想法输入
  -> 假设卡片
  -> 规则说明
  -> 数据清单
  -> 数据质量检查
  -> 信号生成
  -> 回测引擎
  -> 指标评估
  -> 风险解释
  -> 策略报告
```

模块边界：

- 假设卡片：回答为什么可能有效。
- 规则说明：回答何时买、何时卖、持有多久。
- 数据清单：回答需要哪些字段。
- 回测引擎：回答过去会发生什么。
- 指标评估：回答收益和风险是否匹配。
- 策略报告：回答是否继续研究。

## Data And Logic Flow

输入：Day01 的策略雏形。

处理：补齐研究问题、数据字段、交易规则、评价指标和失败场景。

状态：策略从“想法”进入“研究任务”，还不是执行系统。

输出：量化流程画布和报告目录。

反馈：如果数据不可得，回到规则层简化；如果回测失败，回到假设层判断是否还有研究价值。

## Key Technical Points

- 每个策略都要有基准，比如沪深300、中证500或对应 ETF。
- 回测必须说明数据区间、调仓频率、手续费、滑点假设。
- 结果要同时看收益、波动、最大回撤、胜率和持仓时间。
- 不要只保留成功策略，失败策略也要记录原因。
- 策略报告是后续编程落地的需求文档。

## Upstream Dependencies And Downstream Applications

上游依赖：Day01 的策略雏形。

下游应用：Day03 会检查 A 股市场规则对数据和交易的限制；Day04 会把流水线变成代码模块。

## Production Example

策略研究问题：宽基指数超跌后是否存在短期反弹优势？

报告目录：

```text
1. 研究假设
2. 买卖规则
3. 数据来源和字段
4. 回测设定
5. 收益和风险指标
6. 失败阶段分析
7. 是否进入模拟跟踪
```

## Counterexample

错误做法：下载一段行情，调很多参数，挑出收益最高的一组，然后认为策略有效。

问题：这可能只是过拟合。没有事前假设、没有基准、没有风险解释，也没有失败条件。
